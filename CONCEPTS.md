# Concepts

> Shared domain vocabulary for this project — entities, named processes, and status concepts with project-specific meaning. Seeded with core domain vocabulary, then accretes as ce-compound and ce-compound-refresh process learnings; direct edits are fine. Glossary only, not a spec or catch-all.

## Structures and interfaces

### Experimental complex
A structure in the Protein Data Bank, determined experimentally, that contains both proteins of a queried pair as separate chains.
*Avoid:* "predicted complex" for these entries. Predicted multi-chain models are a different thing and are never mixed into experimental results.

### Asymmetric unit
The coordinates exactly as deposited for a crystal structure: the smallest set of chains from which the whole crystal can be rebuilt using its symmetry.

All interface calculations work on the asymmetric unit only. It can still contain contacts that exist only in the crystal, so an interface found there is evidence of a biological interface, not proof of one.

### Symmetry mate
A copy of a chain generated by applying the crystal's symmetry to the asymmetric unit. Symmetry mates describe how molecules pack in the crystal lattice, and contacts with them are excluded from interface contacts. Copies that differ only by a whole-cell lattice shift are a known edge case that is not yet ruled out.

### Chain pair
Two distinct chains of one structure considered together as a candidate interface. When users query a protein pair, the chain belonging to the first queried protein is presented first.

### Interface residue
A residue of one chain with at least one non-hydrogen atom within the contact cutoff of a non-hydrogen atom of the partner chain, measured in the asymmetric unit with waters and ligands removed.
*Avoid:* "binding site" or "hot spot". Those imply measured energetic importance, which proximity alone does not establish.

The set depends on the cutoff: a tighter cutoff always yields a subset of a looser one. Each interface residue records its closest distance to the partner and how many atom pairs fall within the cutoff.

## Integrity

### Provenance
The record attached to every result naming where it came from: the source database, a human-browsable link to the record, the database release when known, and when it was retrieved. Every top-level result carries one, the items inside it inherit it, and it is displayed alongside the result.

### Fabricated output
Any value shown to a user that was not fetched from a source or computed from fetched data, such as placeholder sequences, randomly generated scores, or "fallback" predictions. Fabricated output is forbidden: a missing or failed source is reported as missing or failed, never filled in.

## Compound activity

### Evidence tier
A per-target label summarising how strongly a compound's activity against that target is supported: potent in at least two distinct publications, potent in one publication, or weak/non-quantitative. "Potent" means the standardised potency passes a fixed threshold.
*Avoid:* "confidence" for this label. It counts distinct reports and is not a probability. Distinct publications can still come from the same group, so a top tier is not proof of independent replication.

### Assay interference
Activity readouts caused by a compound disrupting the assay itself (for example by aggregating, redox cycling or reacting covalently) rather than by specific binding to the target. Compounds prone to it, such as polyphenols, make single biochemical hits weak evidence on their own.

## Data access and testing

### Response cache
The single on-disk store of responses from the public data sources. It is used at runtime to avoid repeat requests, and the test suite uses the same store as its recorded fixtures.

Successful responses and "not found" answers are stored. Other errors never are, so a temporary outage is not remembered as a permanent answer.

### Offline mode
Operating purely from the response cache with no network access. Anything not already cached fails loudly instead of being fetched, and cache entries never expire in this mode. Tests run in offline mode by default.

### Record mode
A test run that may reach the network to fill in responses missing from the recorded fixtures, so a new test can be added and its responses committed.

### Live mode
A test run that ignores the recorded fixtures and queries every source afresh. It runs on a schedule to detect upstream changes that recorded fixtures would hide.

## Flagged ambiguities

- "Interface" had been used both for the geometric contact set computed from coordinates and for a biologically validated interaction surface. In this project, "interface" always means the geometric set, and biological relevance is stated separately as a caveat.
